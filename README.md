# 水果掉掉乐 (Fruit Match)

一个给孩子玩的重力消除小游戏，用 **Phaser 3 + Matter.js + TypeScript + Vite** 做，纯静态，部署在 GitHub Pages 上，手机浏览器直接玩。

## 玩法

- 点一下天上钉住的水果 → 它开始受重力往下掉
- 水果落进底部的窄篮子里会堆叠起来
- 两个**相同**的水果**实际碰到一起**才消除（星星特效）——窄管道里水果是串行堆叠的，同类中间隔着别的水果**不会**消除，必须让同类落在堆顶救场
- 篮子只装得下 **3 个**：第 4 个消不掉的水果落进来就**失败**（“装不下啦”）
- **可解锁的预留空位**：第 9 关起整个井**上移一格**、第 24 关上移两格——管道物理加深，底部多出被砖封住的锁定位（水果会真实地落在砖上）。点砖解锁 → 砖消失、整摞水果下沉一格，容量 3 → 4 → 5；同时井上移也压缩了上方棋盘空间，本身就是难度提升。每关重置。**解锁要花一把钥匙**（原版这里是看广告，见下），钥匙不够就是打不开
- **横向漂移（第 19 关起）**：整片钉住的水果每释放 3 个就整体**横移一格**（46px），到 ±70px 边界折返——落点随之左右偏移，和下沉叠在一起，瞄准井口更难
- **木桩（第 14 关起）**：左右屏边探出锯断的圆木桩，之字排布（14 关 2 根 → 26 关 4 根 → 38 关 6 根封顶），只碰撞**已释放**的水果——靠边掉落会被弹开、甚至搁在桩上下不来（打乱可解）；钉住的水果和下沉传送带不受影响
- **整体下移**：一关的水果**在开局时就全部生成好了**——一屏在画面里，其余全部堆在屏幕上方（第 60 关那一堆有 3300px 高，约 2.6 屏）。之后游戏只做一件事：让最下面那颗水果始终离漏斗保持固定距离 H。最下面的被点掉了，整堆就下沉到下一颗顶上那条线为止，上方的水果跟着滑进画面。每关总量远超一屏（第 1 关 34 个，逐关递增到 160 个封顶）

  > 这里**没有任何「生成 / 补货」逻辑**，是刻意的。早先的实现是「只生成一屏 + 其余排队 + 从上方补入」，那套东西前后制造了三次补货死锁和一次「水果凭空出现在刚空出来的位置上」。补货位置算错的 bug，只有在"存在补货"时才可能出现；整堆预生成之后，这一类 bug 在结构上不存在。`spawnFruit` 全局只有一个调用点，就在 `buildBoard` 里。
- **跑遍全国**：141 关对应中国 34 个省级行政区的城市（第 1 关「广东-广州」→ 第 141 关「澳门」），跨省时提示「即将到达 XX！」，全部打完是「跑完全国啦」大结局
- 关卡进度存在 localStorage，关掉浏览器下次接着玩；种类每两关 +1（3 种起步，共 **28 种**：12 种水果打底，蔬菜约第 21 关起登场，第 53 关全解锁）
- **打乱**：真正**重排篮子里的堆叠顺序**（随机交换各水果所在的层），这是交替堆叠（香蕉/草莓/香蕉/草莓）唯一的解法——那种局面下两对水果都在篮里却一个都消不掉；同时给其余散落水果一个冲量解物理卡死

## 答题换钥匙

原版靠「看广告」解锁底部空位，我们换成做题。

- **解锁一个空位 = 1 把钥匙**，左上角显示余额，新玩家送 2 把
- **钥匙只在结算页挣**：过关或失败后点「答题攒钥匙」，一次最多 3 题，答对一题一把
- 答错不扣钥匙，只把算法讲一遍

设计上有一条硬规矩：**题目永远不出现在需要解锁的那一瞬间**。篮子快满了还被按住做题，
孩子恨的会是题而不是游戏。所以挣钥匙放在没人催的结算页，花钥匙才在紧张时刻——
没钥匙就是打不开，等这局结束再慢慢答。

题库在 `src/quiz/`：

| 文件 | 状态 |
| --- | --- |
| `math.ts` | ✅ 11 类生成器（三位数乘两位数、两位数除法、四则运算、运算定律、大数、小数、三角形、面积单位、平均数、角），现算现出，不会背答案 |
| `chinese.ts` | ⏳ 等课本 —— 字词/古诗/日积月累都是按单元逐字指定的，凭空出题对不上进度 |
| `english.ts` | ⏳ 等课本 —— 计划「看图选词」，图直接复用游戏里的 28 张水果蔬菜 PNG |

数学部分和教材版本无关（各版本四年级都学这些），所以先做了。语文英语需要：
版本（人教/苏教/北师大…）、上册还是下册、目录页、当前学到第几单元。

填空的题库会被自动跳过，所以把 `CHINESE_BANK` 填上就自动生效，不用改别的代码。

```bash
npm run check:quiz   # 抽查 6000 道题：选项不重复、答案下标有效、数学题逐题重算
```

## 调试后门（跳关）

在网址后面加 `?level=N` 就能直接进入任意一关，方便测试：

```
https://jiajunhappyelements.github.io/fruit-match/?level=24
```

也可以在浏览器控制台执行 `fmGoto(24)`。

跳关是**临时会话**：右上角会显示「调试 · 不存进度」，通关也**不会覆盖真实存档**，
所以随便跳到第 100 关看看也不会毁掉孩子的进度。去掉参数刷新即回到正常进度。

## 本地开发

```bash
npm install
npm run dev      # 打开 http://localhost:5173（手机连同一 WiFi 用电脑 IP 访问）
npm run build    # 产出静态文件到 dist/
npm run preview  # 本地预览打包结果
```

## 部署到 GitHub Pages

1. 新建一个 GitHub 仓库并把代码 push 上去（分支 `main`）。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**。
3. 每次 push 到 `main`，`.github/workflows/deploy.yml` 会自动构建并发布。
4. 访问 `https://<你的用户名>.github.io/<仓库名>/`，手机扫码即玩。

> `vite.config.ts` 里 `base: "./"` 用的是相对路径，所以放在任意子路径都能正常加载资源。

## 代码结构

```
src/
├── main.ts              # Phaser 游戏配置（分辨率、缩放、物理）
├── config.ts            # 所有可调参数：种类/关卡曲线、井几何、解锁位、木桩……
├── art.ts               # 程序化纹理：天空/地形/篮子/砖块/木桩/按钮（零图片素材）
├── levels.ts            # 141 关的省市旅程（进度皮肤，和难度完全解耦）
├── quiz/                # 答题换钥匙：题库 + 钥匙钱包 + 结算页答题面板
└── scenes/GameScene.ts  # 全部玩法：钉板 / 掉落 / 堆叠 / 消除 / 判负 / 传送带 / 解锁
```

想调手感先看 `src/config.ts`。
